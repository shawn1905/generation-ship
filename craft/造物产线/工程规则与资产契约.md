# 工程规则与资产契约 v0.1

## 资产四层身份

`family`（产品族）→ `model`（型号）→ `instance`（具体物证）→ `revision`（构型版本）。故事引用实例或版本；模型不因一张渲染图而改变。

## 最小规格卡字段

```yaml
asset_id: EXP-...
status: experimental | candidate | canon
coord: dimension × epoch × space_band
purpose: one sentence
environment: gravity, pressure, temperature, radiation, dust
envelope_m: [x, y, z]
interfaces: [{id, position_m, axis, clearance_m, load_case}]
materials: [{part, candidate, evidence_status}]
manufacturing: process, feedstock, external_inputs
maintenance: access, replaceable_parts, isolation_method
parameters: source_file, generator, revision
validation: [E0, E1, E2, E3]
limits: [claims_not_verified]
sources: [{fact_id, path, locator}]
```

## 永久规则

- Blender 内部单位统一为米，Z 轴向上；导出后必须用标尺验证轴变换。
- 任何外形特征必须能归因于任务、环境、结构、制造、维护或识别；无法归因的细节标为展示层或删除。
- 结构源、参数源、展示材质、Unity 场景分离保存；展示不得覆盖源模型。
- 所有运动件必须记录自由度、行程、间隙、停止位和失效位；只做静态灰模时明确写“未实现运动”。
- 接口优先于装饰：位置、方向和配合范围是共享资产的稳定合同，修改必须递增 revision。
- 证据不足时降低断言等级，不用精确数字制造确定感；`experimental_assumption` 不得被下游改写成 `canon`。
- 几何检查、工程估算和专业认证分开记录；AABB 只能是粗筛，不能叫碰撞证明。
- 每次发布记录生成器版本、参数哈希、输出哈希和未解决问题；二进制大文件本地定稿后一次入库，遵守项目 Git 规则。

## agent 返回格式

```text
STATUS: PASS | FAIL | BLOCKED_INPUT
ARTIFACTS: <paths>
MEASURED: <3-6 key values>
CHECKS: <commands and result>
LIMITS: <claims still unverified>
NEXT: <one smallest next job>
```

禁止返回完整日志；失败只返回第一处根因和复现命令。这样主 agent 能在最小上下文内作出下一步决定。
