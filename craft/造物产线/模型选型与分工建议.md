# 造物产线模型选型与分工建议

> 状态：建议稿（2026-09-06）  
> 适用范围：世代飞船项目的世界观推演、工程规则、3D 资产生成与质量检查

## 建议结论

采用分层模型架构，不让所有任务都使用旗舰模型：

```text
GPT-6 Astra：总架构与最终裁决
GPT-5.6 Sol：深度工程审查与矛盾仲裁
GPT-5.6 Terra：Blender / Unity / 资产流水线主力
GPT-5.6 Luna：批量资料抽取、格式整理和低风险检查
Blender / Unity：确定性建模、导入、运行和验证
Git + 工单：隔离并行修改，保留审计记录
```

## 角色分工

| 角色 | 推荐模型 | 主要任务 |
|---|---|---|
| 总架构 Agent | GPT-6 Astra | 技术发展路线、跨文档一致性、核心规则、最终决策 |
| 工程审查 Agent | GPT-5.6 Sol | 物理约束、结构逻辑、证据核查、设计评审 |
| 生产 Agent | GPT-5.6 Terra | 参数化 Blender 脚本、Unity 流程、资产工单和验证 |
| 批处理 Agent | GPT-5.6 Luna | 文档抽取、元数据整理、格式转换、简单 QC |
| 视觉参考 Agent | 图像模型 | 概念草图、材质和风格参考，不作为几何依据 |

## 使用规则

1. Astra 只处理高影响决策、跨系统冲突和最终合并意见。
2. Sol 在涉及硬科幻物理、制造可行性、设定矛盾时介入复核。
3. Terra 承担大多数资产生产任务，输出脚本、参数、日志和可复验文件。
4. Luna 只接收结构化上下文包，不承担世界观裁决或关键工程结论。
5. 模型负责推演、规格和代码；Blender/Unity 负责实际生成与确定性验证。
6. 每个任务必须通过工单、资产契约和质量门，不以模型自述“完成”为验收依据。

## 成本控制

默认采用 **Astra + Terra**；出现跨领域冲突时调用 Sol；资料搬运和批量检查交给 Luna。上下文使用 C0/C1/C2 分层包，避免把整个项目重复注入每个 Agent。

## 调整触发条件

当出现以下情况时升级模型或增加审查：

- 新资产改变既有技术树或世界规则；
- 资产涉及承压、热管理、辐射防护、接口兼容或维修闭环；
- Blender/Unity 验证失败且原因跨越多个系统；
- 正典文档之间出现时间、数量、编号或因果冲突。

模型名称、能力和价格以[OpenAI 官方模型目录](https://developers.openai.com/api/docs/models)为准。本文件是项目内部建议，不构成永久锁定；每季度或模型目录发生重大变化时复审。
