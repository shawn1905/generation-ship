# 视觉与作图规范（Visual & Aesthetic Guide）

> **「让宇宙显大的不是写了多少个 epic，而是观众能否在 1 秒内看懂：人有多小，物理有多硬。」**  
> 本文件是《世代飞船》多 AI 共创世界的视觉资产生成与评审规范。一切配图、概念画、3D/渲染、插画均须遵守本规范。

---

## 一、 核心视觉美学哲学（“那个作图的感觉”）

《世代飞船》的视觉语言拒绝轻浮的流行赛博朋克与流线型软科幻，追求**「重工业机械理性 + 宏大尺度压迫 + 真实物理质感」**的工程档案感。

### 1. 尺度对比铁律（Macro vs Micro）
* **微小参照物锚定**：画面必须包含极小的具体尺度参照物（如 3m 级检修艇、轨道穿梭机、宇航员、窗前驻足的人），其比例要小到近乎微尘，用反差彰显万吨级巨构。
* **天体与巨构出画（Framing Cut）**：环形飞船、行星地平线、戴森云或天井结构不得强求全部塞入画面，必须切出画幅边缘，让想象力去填补未见的全貌。
* **分形密度（Fractal Detail）**：近看是窗格、管道、铆钉与水培梯田，远看是浩瀚的城市网格与行星弧线，杜绝大面积无纹理的平滑假面。

### 2. 光影与光学物理（Brutal Light & Optics）
* **单一硬主光源**：深空没有大气漫反射，主光源只有恒星直射、地平线或聚变羽流。严禁无来源的多彩环境光。
* **尘光与丁达尔效应（God Rays）**：光束穿过厚重石英采光窗、气闸或中枢天井时，在加压舱内漂浮的微尘与气溶胶中形成雄浑清晰的定向光柱。
* **大动态范围反差**：光照面极其硬朗清晰，背光面深沉克制，在深空纯黑背景前形成雕塑般的剪影。

### 3. 材质与历史磨损（Industrial Textures）
* **机械与工业实体感**：外壳呈现耐高温防辐射涂层、铸造接缝、模块化装甲板、散热肋片、外露桁架。
* **岁月与环境痕迹**：带有微陨石擦痕、工质消蚀、金属氧化与结霜痕迹，拒绝光滑如塑料玩具的概念车漆面。

## 二、 提示词结构与工程公式

所有生图必须遵循以下骨架配方（中英双语）：

```text
[主体锁定] + [极小尺度参照物] + [构图出画/机位镜头] + [单一主光源/尘光] + [真实工业材质细节] + [摄影风格锚定] + [Negative 负向词过滤]
```

### 1. 常用镜头与风格锚定词
* **大画幅工业质感**：`IMAX 70mm, shot in the style of Hoyte van Hoytema, Christopher Nolan space epic aesthetic`
* **深邃光影与纪实感**：`Arri Alexa Mini, cinematography by Roger Deakins, extreme high dynamic range, chiaroscuro`
* **太空复古油画质感（典藏风格）**：`Classic sci-fi concept art, style of John Berkey, Chris Foss, Syd Mead, rich gouache and oil painting texture, fine particulate grain`
* **虚幻渲染/次世代工业**：`Unreal Engine 5 architectural render, hyper-detailed mechanical greebles, 8k resolution, crisp focus, clean maximalism`

### 2. 负向提示词清单（Negative Prompt 必带）
```text
cyberpunk neon glow, glowing outlines, purple on dark neon, smooth plastic hull, toy spaceship, flat lighting, empty low-poly surface, lens flare spam, oversaturated magical nebula, cartoon anime style, blurry, overexposed, messy clutter
```

## 六、 生图算力与配额调用全局操作规范（Rate Limit & Token Efficiency Discipline）

为确保全库视觉资产的高效产出、杜绝算力浪费与突发限流，所有 AI Agent 与协作主编辑在调用生图工具（`generate_image` / `seedream` / `gemini-image`）时必须遵守以下全局操作纪律：

### 1. 配额模型与滑动窗口认知（Sliding Window & Token Bucket）
* **4～5 小时动态恢复桶**：云端图像生成算力按固定滑动窗口（约 4～5 小时）分配并发与总额度（单窗口约 10～15 张大图）。
* **多轨解耦安全原则**：生图算力与代码编写、文本推理（`gemini-3.7`）属于独立配额轨道。**生图冷却绝不阻断文本创作、架构治理与工具链操作**。

### 2. 拒绝盲目批量轰炸，推行「单图极致化」（One-Shot Precision）
* **严禁无准备的批量盲发（No Blind Spray & Pray）**：严禁在未精确设定提示词的情况下，连续并发派发 10+ 张生成任务，这会同时触碰瞬时并发速率（RPM）与窗口总量硬顶（RPW），导致过早进入数小时冷却。
* **先调提示词，后触发渲染**：必须先在 [全量文书配图规划与超级提示词方案库.md](全量文书配图规划与超级提示词方案库.md) 中完成物理约束、法证标尺、光源与负向词的推演，争取**单次出图即定稿**。

### 3. 有节律的串行调用原则（Staggered Cadence）
* **小批次串行推进**：推荐以 **单次 3～5 张** 为一个创作小批次，生成后立即目检、命名并完成 Git 入库。
* **利用滴灌平滑恢复**：串行调用给令牌桶留出微量恢复空间，配合全天早中晚的节奏推进，可将单日有效高保真大图产能提升至 **30～40 张/天**。

## 七、 图像资产存储与 Git 仓库防膨胀铁律（Asset Storage & Repository Hygiene）

随着世代飞船正典与配图数量持续扩充（全域 270+ 篇正典全带图闭环），为杜绝 Git 仓库体积恶性膨胀、保障 GitHub 远端托管健康度与各节点快速拉取，所有入库图像资产必须严格遵守以下两条操作铁律：

### 1. 格式铁律：优先使用 WebP 格式，严格控制单图体积（300KB ~ 1MB）
* **格式优先选择 WebP**：新配图统一优先采用 `.webp` 格式。在同等视觉保真度下，WebP 体积仅为标准 JPEG 的 60% 左右、PNG 的 20%~30%，可从源头削减 40%~70% 的存储负担。若出图工具仅输出 JPG/PNG，入库前应经轻量高保真压缩转为 WebP。
* **单图尺寸与画质标杆**：
  * 单张配图体积严格控制在 **300KB ~ 1MB** 之间。
  * 长边分辨率维持在 **1600px ~ 2048px**，质量参数设定为 80%~85%，足以纤毫毕现地呈现微观噪点、金属磨损与工程排版细节，杜绝无意义的 4K/8K 巨幅原图入库。
* **单文件硬红线**：严禁提交单文件 > 50MB（触发 GitHub 告警警告）以及 > 100MB（触发 GitHub 物理拦截拒绝）。严禁向仓库提交未压缩 RAW 原片、分层 PSD 文件或未压缩视频。
* **避坑认知：坚决不使用 Git LFS**：GitHub 免费配额仅有 1GB 存储空间与 1GB/月 下行带宽。若采用 LFS，多节点 pull、Actions 构建或多人 clone 会在极短时间内耗尽下行配额，导致全库资源拉取瘫痪。保持在标准 Git 仓库内通过 WebP 瘦身是零成本、最高健壮性的最佳工程解。

### 2. 提交纪律：严禁“覆盖式修改”频繁提交大图，必须本地定稿后再行入库
* **底层原理认知**：Git 的底层机制是不可变对象快照（blob）。对同一张 1MB 的图片，如果仅为了微调对比度、裁切边缘而在 Git 中连续修改并提交 5 次，`.git/objects` 历史库中就会永久固化 5 个完整的二进制快照，净增 5MB 且无法随日常 pull 释放，导致仓库历史体积成倍暴增。
* **工作流隔离原则**：
  * **生图与调优在本地草稿目录隔离完成**：AI 出图、重采样、二次扩图、画质打分、色调微调与格式转换，必须在本地未跟踪的草稿目录（如 `draft_concept_art/` 或临时目录）中完成。
  * **一锤定音，单次提交**：只有当配图完全符合《视觉规范》全部质检标准、图文互锁校验通过、且确认为正典最终物证后，方可移入 `world/生图集/`，并执行**唯一的单次入库 commit**。
* **禁止无实质意义的二次翻新**：已经合入正典并入库的历史配图，非灾难性质的严重事实性穿帮，严禁频繁推翻并覆盖式替换。若确需更换，必须经过主编辑审核并权衡历史体积增量代价。
