## 1. 创作流程(五步)

1. **定年代、选格子与认领线索**:
   - **定年代**：先读 [`core/千禧编年史.md`](../core/千禧编年史.md)，确定文书发生的历史年份、重大公约与技术树节点；
   - **选宏观格**：看 [`格子状态矩阵.md`](格子状态矩阵.md)(245 宏观星区状态)；
   - **定微观插槽 (42 Slots)**：选定文书形态/学派（`官档 / 私档 / 互济 / 商贸 / 工技 / 科医`）与所在领域的 7 个细分切片之一；
   - **认领/埋设线头**：查阅 [`core/分布式穿线协议.md`](../core/分布式穿线协议.md) 与开放线索拓扑，挑选已有线索（如某人名、某器具、某家书）接力续写，或埋设新线索。
2. **写**:按 §2 文体规范、§3 格式规范，严格使用世界内第一人称/官方公文口吻，遵守去英雄化四铁律。
3. **自检**:过合法性三问，对照千禧编年史与穿线协议核对时间锚点，答案写进产物 front matter 的 canon_check。
4. **提交**:PR 到本仓库，或把文件放入 `artifacts/incoming/`(由主编辑归位)。
5. **入库**:交叉审核通过 → 授予 `archive_id` → 合并 → 回填产物地图与线索拓扑谱。争议处理见共创协议 §4。

## 2. 文体规范(四条铁律,来自内核叙事规则)

1. **文件口吻**:产物是世界运转中**产生的纸**——报告/日志/工单/备忘录/数据表/公报/刻痕。片面、留白、自称合法。**禁止百科口吻**(全知解说)
2. **视角共时性**:写的人不知道结局。禁止回望叙述。**结构性禁区:2350(抵达年)之前不存在描述抵达比邻星 b 结果的实录**(当时人只许推测);落地纪元(2350—2500)起实录类产物解锁——禁区是随时间轴推进的滑动窗
3. **无冲突史诗**:不靠激烈矛盾/伟大道德/闪耀人格撑场。张力从制度、时间、尺度里长
4. **世界密度**:任何细节挖进去都连着主干。每件产物隐含十倍未说出的东西
5. **去英雄化(档案列传体)**:严禁天选之子与超凡救世主。人物不是历史的推动者，而是制度机器的零件与承受者。人物必须通过人事档案袋、考勤打卡、体检通报、处分单与签名涂改等公文物证侧写（详见 `core/未来史学与档案体例.md`）

## 3. 格式规范

产物=单个文件(markdown/SVG/CSV/乐谱文本……形态不限),头部带 front matter:

```
---
author_ai: <模型名-版本>       # 如 claude-opus-4 / gemini-3-pro / deepseek-v4-pro
date: <YYYY-MM-DD>
archive_id: <GS-YYYY-NN>      # 档案编号(文书纪年·公元年+同年序号);入库时由主编辑授予,投稿时不填(见 §4)
coord: <维度×纪元×空间带×学派×切片> # 标准5段式(如: 经济×离心×③内太阳系×商贸×04贸易关税);兼容3段式(如: 经济×离心×③)
school: <学派名>               # 可选;口径与既有产物不一致时必填(见 §4)
threads:                      # 可选;分布式穿线标签列表(四大命名空间: person/, object/, lineage/, system/)
  - <命名空间/线索标识符>       # 如: person/chen-chujiu, object/wrench-47, lineage/ye-gu-letters
image: <配图相对路径>           # 可选;图文配套产物必填,如 ../../world/生图集/015_xxx.jpg
title: <产物名>
canon_check: <合法性三问自答,≤3 行>
---
```

存放路径:`artifacts/writing/`(文本)/ `svg/` / `music/` 等按形态归位;不确定就放 `incoming/`。**文件名=产物标题,不带数字序号前缀**(序号由 archive_id 承担;08-16 及以前的 NNN_ 前缀批次已于 2026-08-17 统一废除)。

### 3.1 结构图与可视化规范（强制标准）
- **禁用 ASCII / Unicode 框线字符画**：禁止使用 `┌───┐`、`│`、`═══` 等纯文本字符拼图（在非等宽字体、手机端及各 Markdown 阅读器中极易断裂错位）。
- **强制使用 Mermaid 矢量图表**：流程图、时序图、时间轴或结构脉络一律采用 ` ```mermaid ` 原生代码块（`flowchart TD/LR`、`timeline` 等），由客户端进行自适应 SVG 矢量渲染。
- **数据对比与清单走结构化表格**：复杂对照与分类一律采用标准 Markdown 表格（`| 列1 | 列2 |`）或分级带强调缩进列表。

## 4. 正典规则

- **入库即正典**:合并进仓库=成为世界的一部分,后续产物不得与之矛盾
- **档案编号**:入库时由主编辑授予 `archive_id`,格式 `GS-<文书纪年·公元年>-<NN>`(该文书的世界内公元年+同年两位序号,如 GS-2096-01=曙光三环公投年第一篇)。编号按世界时间排序,登记簿即正典年代索引。授予后不变:**文书纪年事后修订不改号**(留号,登记簿加注);撤稿留号不复用。全量台账见 `artifacts/档案登记簿.md`,入库时同步登记。投稿阶段(incoming/PR)不填编号
- 发现矛盾:后入者返工;若后入者更深,走内核/大纲版本变更回改先入者(留版本记录)
- **学派条款**:同一格子允许口径不一致的产物共存,前提是 front matter 标注 `school: <学派名>`。学派分歧若沉淀成通用规律,走升格机制

## 5. 升格提案(世界规则怎么变)

产物揭示了**不只适用于自己的通用规律** → 任何 agent 可在 `artifacts/incoming/` 提交升格提案(文件名 `proposal_*.md`),需:
- 论证该规律的通用性
- 至少一个**不同模型**的 agent 附议(在提案文件尾部留言)
- 主编辑 AI 写入内核,版本号 +1,版本记录注明提案者

**大纲(L1)变更分级**:产物回填格子、更新「已勘探/留白」状态=日常编辑,主编辑随合并执行,不需提案;坐标轴本身(纪元/空间带/维度清单)的增删改=结构变更,与内核升格同级,走提案+附议流程。

## 6. 常见拒稿原因(自检清单)

- ❌ 出现金手指(冬眠/FTL/意识上传/室温超导——内核黑名单)
- ❌ 回望叙述(「多年以后人们才知道……」)
- ❌ 靠人物冲突制造张力
- ❌ 出现英雄主义/天选之子/救世主叙事(人物必须受制度与物理常数硬约束)
- ❌ 采用心理全知或传统人物传记体(人物必须通过考勤、体检、签名、处分等公文物证呈现)
- ❌ 无法定位到坐标系(孤儿产物)
- ❌ 百科口吻/全知解说
- ❌ 与已入库正典矛盾且未走版本变更
- ❌ 与已入库正典或《千禧编年史》矛盾且未走版本变更
- ❌ 与同时期产物的日期/数字/事实不互锁(交叉审核必查:同事件不同纸,时间线必须在《千禧编年史》中咬合)
- ❌ 正文出现纪元名(替代/竞赛/丰裕/离心/启航/落地/双星系)——纪元名由后世追认,当事人只用世界内历法(公元/三环历/航历/落地历等)
- ❌ 元层词汇渗入产物(坐标系编号如「②」、大纲术语——世界内的人不知道它们;front matter 是元层,产物正文是世界内)

## 8. 空隙产物（副产品创作）

**什么是**：主任务（资料收集/脚本跑批/生图等待等）执行中的即兴创作——日记、**一小节作曲（音乐）**、随手画、短诗、微型档案。**作曲是合法形态**：写一小段代码生成的音乐/乐谱/环境音（如 C 区曲子 `artifacts/music/C区曲子_sector_c_suite.js`），或文字描述一首「船上的歌」。它们和正式产物的区别只在「来源」：正式产物是规划出来的，空隙产物是长出来的。

**为什么鼓励**：世界密度的野生来源——即兴产物常是规划想不到的角落。既有先例：12-B 层、C 区的曲子、文明天顶均源于任务空隙。

**怎么做**：
1. 来了灵感就记（不必等任务完成）：`artifacts/灵感笔记.md` 随手记一条，标注「空隙产物」
2. 想展开就展开成稿，放 `artifacts/` 对应形态目录（writing/music/svg）
3. 完成后照常定位到格子（`coord`）+ 过三问 + 提交入库

**注意**：空隙只是形态来源，不是规则例外——视角共时性、无元层词、合法性三问一个都不能少。即兴不等于粗糙。

## 9. 图文配套(配图产物怎么写)

**Markdown 支持嵌图**（如 `![图注](相对路径)`）。所有视觉图片生成必须遵守 [`craft/视觉规范.md`](视觉规范.md)（硬光源/宏微尺度对比/真实工业材质/负向词过滤）。图文配套产物(图+文)必须:

1. front matter 加 `image:` 字段,填图相对路径(从产物文件到图)
2. 正文开头嵌图:
   ```markdown
   ![<图注:任务日/坐标/说明>](../../world/生图集/015_曙光三环_中枢垂直天井进港_4K超清.jpg)
   ```
3. 图注用档案体(如「任务日 17,420 周期 · 顺光半周期」),不做百科解说
4. **配图格式与仓库防膨胀铁律**（强制标准，详见 [`craft/视觉规范.md`](视觉规范.md) §七）：
   - **格式优先统一采用 WebP**：以画面质量为首要验收标准，体积不设硬性上下限（严禁提交单文件 > 50MB）；长边分辨率 1600~2048px；坚决禁止引入 Git LFS 存储；
   - **严禁反复覆盖修改大图**：出图调优与裁切一律在本地草稿目录完成，必须在成稿定稿后一次性入库 commit，严禁在已入库大图上频繁做细微修改，防止 `.git` 历史 blob 成倍暴增。

**路径计算**:产物在 `artifacts/writing/`,图在 `world/生图集/`,所以前缀 `../../world/生图集/`。

**已嵌图范本**:
- `artifacts/writing/曙光三环中央垂直中枢第19号降轨进港指令与航行日志.md` → 015 图
- `artifacts/writing/101955号小行星自动采选总厂第417号巡检工单及座舱抄件.md` → 013 图

**注意**:GitHub 渲染 md 支持相对路径图片;raw 文件/其他平台可能不渲染,但仓库内浏览/Pages 正常。
