# 通信协议不兼容事件通报

**发布单位**：联合体深空通信署　**通报编号**：ENG-INC-3753-019
**事发**：3753年10月18日　**结案**：3753年10月25日　**经办**：通信协议工程师姚通联

## 一、通信日志与签认书（物证）

> **接收端日志·原行**（3753年10月18日上午八时，通信协议工程师姚通联（见GS-3758-01）例行检查照录）：
> 　前一日夜间至今晨，我方接收端不能解码异星方信号；终端屏显解码错误，错误码为通信协议（见GS-3768-01）未定义之新码值。
> **异星方回函摘录**：其方通信设备于10月17日夜间固件升级，信号编码格式有变更，未提前通知我方。
> **故障签认书·姚通联手书**："对方升级不通知，我方也有责任——没有建立定期通报机制。"签名，日期在案。

## 二、处置时刻表

| 时刻（10月18日） | 事项 | 经手 |
|---|---|---|
| 上午八时 | 例行检查发现解码错误 | 姚通联 |
| 八时十五分 | 经应急语音线路联系异星方通信工程师 | 姚通联 |
| 八时三十分 | 确认异星方夜间固件升级 | 双方 |
| 九时 | 请求异星方提供新固件解码参数 | 姚通联 |
| 下午二时 | 收到参数，重新配置我方接收端 | 姚通联 |
| 下午四时 | 通信恢复 | 姚通联 |

故障持续六小时。中断期间双方外交往来以人工信使临时维持：信使由驻"晶环"站联合科考队（见GS-3755-01）人员担任，往返双方使馆传递书面函件；重要函件虽延迟未丢失。信使交接存根逐班签收，附卷。

## 三、故障原因（调查认定）

异星方设备固件升级后信号编码格式变更，我方接收端未更新解码参数，不能识别新格式信号。深层：双方无定期通报机制。

## 四、整改清单（附执行凭证）

1. 双方约定每季度通报一次设备维护计划；
2. 任一方固件升级前须提前三十天书面通知对方；
3. 建立应急人工信使机制，通信中断时启用；
4. 姚通联在维护清单中增加异星方固件版本检查项（新增勾选栏，见维护清单）。

技术组另拟三套备选转换方案，均在七十二小时内完成验证，采用第二套——增设协议转换网关，部署于使馆通信枢纽，日常维护由通信组负责；后续每季度兼容性演练一次。固件升级前兼容性测试环节自3753年11月起执行，升级前先在测试环境验证。

## 五、月度会晤纪要与结案签批件

> **会晤纪要·双语件**：姚通联与异星方通信工程师建每月技术会晤机制，内容含设备运行状态通报、下月维护计划通报、协议版本同步确认。纪要双语缮写，双方各执一份，自3753年11月起执行。此后未再发生因固件升级未通知导致之中断。
> **结案报告**（3753年10月25日）：姚通联撰，通信署签批存档。结论：故障系异星方固件升级未通知所致，双方已建季度维护计划通报机制。

年度：通信保障3753年度中断三次，均已修复；季度技术例会四次均按时举行。

> 记录人注：无机密泄露，无函件丢失，六小时复原。姚通联技术保障总结留档一句——"跨文明通信最大的敌人不是距离，是对方升级了你不知道。"例会频率维持，不增不减。档案记到此为止。
