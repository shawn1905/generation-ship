# 跨星系首批调度物资延误致鲸鱼座τ星补给短缺事件复盘与整改报告

**编制单位**：跨星系贸易与产业部 / 物流调度组
**报告性质**：事故复盘（含时间线、定责与整改）
**日期**：3010年8月19日

---

## 一、事件简述

3010年4月至6月，联合体统一调度发往鲸鱼座τ星"鲸港—绿原带"的两批关键补给（地下城市生命保障备件、医用同位素、冬季储粮增补）先后延误，最早一批较计划晚抵四十七天，最严重时鲸港三号地下城市生命保障备件库存跌破警戒线。事件无人员伤亡，但险些引发局部减压演练。物流调度组按"事不过夜、件件留痕"原则复盘，成本报告。

## 二、时间线（据舱单与信道记录复原）

| 日期（协星标准时） | 事件 |
|---|---|
| 3010-03-02 | 两批补给在新海市集中集运，凭集中招标合同（GS-3014-01此前已试运行）发运； |
| 3010-03-19 | 承运班船在新海—鲸港中途遇星际尘埃云，减速避险（参照此前同类事件GS-2990-01）； |
| 3010-04-11 | 调度组首次收到减速通报，未升级，判为常规； |
| 3010-05-02 | 鲸港三号城市备件库存跌破安全线，发求救报文； |
| 3010-05-09 | 调度组启动应急调运，就近从太阳系方向另一艘班船转驳； |
| 3010-06-18 | 转驳补给抵港，短缺解除； |
| 3010-07-04 | 原延误班船抵港。 |

## 三、根因：不是天灾，是流程

物流调度组不把责任推给尘埃云。尘埃云减速是常态（已有先例），真正的问题是：

1. **预警不升级。** 3010-04-11首次收到减速通报时，值班调度按"常规延误"处理，未核对鲸港库存曲线。直到库存破线（05-02）才反应过来——中间空跑了二十一天。
2. **集中调度与本地库存脱节。** 3014年才正式立法的集中招标制度（GS-3014-01）此前系试运行，鲸港本地库存数据并未实时接入新海市调度中心，调度方"看不见"鲸港还剩多少。
3. **应急转驳慢。** 05-09决定转驳后，从太阳系方向调船到鲸港仍花了四十天——不是船慢，是跨系紧急调拨的审批流程当时没有绿色通道，按常规合同流程走。

## 四、定责（不讳言，但不扩大化）

物流调度组核定：

- 值班调度（当班四人）：预警不升级，各记工作过失一次，扣当年绩效分，不撤职——因为制度上当时并无"必须核对库存"的明文；
- 调度组组长：负管理责任，诫勉谈话；
- 新海市集运港：无责，按约发运；
- 承运班船：无责，遇尘埃云避险系正确操作。

**特别说明**：本次事故不追究个人"玩忽职守"，因为问题的根子是制度尚未就位——库存数据未联网、应急无绿色通道。个人只是在一个有洞的流程里按旧习惯走路。整改要补的是流程的洞，不是把走路的人办了。

## 五、五项整改

1. 鲸港及三系全部关键城市库存数据，实时接入新海市调度大屏（此为"罗盘"统一调度系统，见另件GS-3028-01的先声）；
2. 设立跨系紧急调拨绿色通道，生命保障与医疗物资的紧急调拨可先动船、后补合同；
3. 任何跨系班船减速通报，一律自动比对目的地库存，破线即自动报警，不依赖值班人记忆；
4. 与航运保险与风险对冲市场（GS-2935-01）联动，对延误损失自动启动理赔，不再人工讨价；
5. 每年至少一次跨系补给应急演练，由安全与应急协调部（GS-3033-01紧急事态法前身）督办。

## 六、鲸港一方的态度

复盘会在鲸港召开。鲸港代表没有指责，只提了一句原话，调度组原样录存："我们不是怪新海市慢，我们是希望下次你们在我们见底之前，就已经在船上了。"

调度组认为这是本份报告最重要的一句。整改五项，就是为了做到这句话。
